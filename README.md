# 로컬 에이전트 파일럿 — 기술 노트

## 1. 왜 만들었나
신용협동조합 창구에서 일할 때, 반복되는 규정 확인과 상담 메모 정리에 AI를 쓰고 싶었지만 보안 규정상 클라우드 AI는 쓸 수 없었다. USB 반입도 건별 허가 대상이고 고객정보는 어떤 형태로도 외부로 나갈 수 없는 환경이다. 퇴직 후, 그때 필요하다고 느낀 도구를 개인 PC 안에서만 도는 로컬 에이전트로 직접 만들어 보았다. 순수한 궁금증에서 출발한 개인 파일럿이다.

## 2. 설계 원칙
- **로컬 완결**: 추론·색인·저장이 전부 한 대의 PC 안에서 끝난다. 외부 API 호출이 구조적으로 없다 (모델 서버는 localhost 전용, 계정 가입 자체가 필요 없는 실행 방식을 택했다).
- **마스킹 우선**: 주민등록번호·계좌번호·전화번호·카드번호·이메일·성명 패턴을 탐지해, 모델에 입력되기 전에 가린다. 원본 데이터는 기기 밖으로 나가지 않고, 모델이 보는 것도 마스킹된 텍스트뿐이다.
- **근거 기반 답변**: 업무 문서 폴더를 색인해 두고, 답변은 색인된 문서 안에서만 생성한다. 근거가 없으면 "문서에서 확인되지 않습니다"라고 답하게 했다 (창구 업무에서 지어낸 답은 사고로 이어지기 때문).
- **폐쇄망 반입 가능성**: 추가 클라우드 계정이나 외부 패키지 없이, Python 표준 라이브러리만으로 동작하게 만들었다.

## 3. 환경과 모델 선택
- PC: Intel i7-8700 / RAM 16GB / NVIDIA RTX 2060 (VRAM 6GB) / Windows 64비트. NPU가 없는 구형 PC라는 제약이 오히려 설계 기준이 됐다 — 화려한 모델이 아니라 이 사양에서 실제로 도는 모델을 골라야 했다.
- 실행: Ollama 0.40.14 로컬 서버 (localhost:11434 전용).
- 모델: EXAONE 3.5 (LG AI연구원, 한국어 특화 오픈 모델). 7.8B(Q4)를 기본으로, 2.4B를 속도 대안으로 실측 비교했다. 문서 검색과 마스킹은 모델이 아니라 색인·정규식이 담당해 두 모델의 적중이 같았고, 차이는 생성 속도와 답변 품질뿐이었다. 그래서 용도를 나눴다 — 근거 답변이 필요한 질의는 7.8B, 빠른 메모 요약·분류는 2.4B.
- 문서 검색: 외부 라이브러리 없는 문자 n-gram 코사인 색인 (문서 단락 단위).
- 설치 중 실제로 겪은 제약: 이 PC의 C드라이브 여유가 약 3.6GB뿐이라 4.8GB 모델을 받을 수 없어, 모델 저장소를 여유 있는 드라이브로 분리했다. 현장 PC의 디스크 사정까지가 배포 조건이라는 걸 확인한 셈이다.

## 4. 만든 것
- `agent.py` — 대화형 에이전트. 문서 질의응답 모드와 상담 메모 마스킹+요약 모드. 질문 자체에 개인정보가 섞여 있어도 모델에 보내기 전에 마스킹한다.
- `docs/` — 데모용 가상 업무 문서 2종 (실제 금융기관 내부자료가 아닌 창작 샘플).
- `bench.py` — 실측 스크립트. 응답 속도, 문서 검색 적중, 마스킹 탐지를 자동으로 재서 results.json으로 남긴다.
- `measure.py` — GPU 적재 상태와 속도 관계를 따로 확인한 진단 스크립트.

## 5. 실측 결과 (bench.py 측정, 2026-11-04, RTX 2060 6GB)
- **응답 속도 (400토큰 생성 기준)**
  - EXAONE 3.5 7.8B: **33.6 tokens/s** (튜닝 후, 아래 참조)
  - EXAONE 3.5 2.4B: **108.5 tokens/s**
  - 튜닝 과정: 7.8B 기본 설정에서는 8.5~9.8 tokens/s에 그쳤다. 원인을 확인하니 모델 5.49GB 중 4.16GB만 VRAM에 올라가고 나머지가 CPU로 내려가 있었다. 전 층을 GPU에 올리도록 지정하자 VRAM 적재가 5.05GB로 늘고 속도가 29.1 tokens/s로 뛰었으며, 최종 설정(컨텍스트 4096 + 전층 GPU)에서는 33.6 tokens/s를 기록했다. 6GB VRAM에서 7.8B를 돌릴 때는 이 적재 설정이 성능을 좌우했다.
- **문서 검색 적중: 5/5** — 샘플 질문 5개 전부 의도한 문서를 1순위로 찾았다.
- **마스킹 탐지: 10/10** — 샘플 문장의 민감 패턴 10건을 전부 탐지했다. 단, 첫 측정에서 카드번호가 계좌번호 패턴에 먼저 걸려 뒷자리 4자리가 남는 부분 노출을 발견했다. 패턴 적용 순서를 카드번호 우선으로 고친 뒤 전문이 가려지는 것을 재측정으로 확인했다. 탐지 개수만 세는 지표였다면 놓쳤을 문제라, 마스킹 결과 문자열까지 검사하는 방식으로 측정했다.
- **종단 동작 확인**: "보이스피싱이 의심되는 이체 요청을 받으면 어떻게 해야 하나요?"에 문서 기반 절차 답변 + 근거 문서 표기, "고액 현금거래는 얼마부터 보고 대상인가요?"에 "1천만원 이상"이라는 문서 수치 그대로 답변하는 것을 확인했다. 상담 메모 마스킹+요약도 마스킹 기호를 유지한 채 요약됐다.
- **오프라인 동작**: 코드의 네트워크 호출 지점은 localhost 한 곳뿐이며 외부로 나가는 연결이 없다. 네트워크를 끊은 상태의 실행 캡처는 별도 증거로 첨부한다.

## 6. 한계와 다음
- 내용이 빈약한 입력(제목만 있는 메모)에서는 모델이 없는 내용을 지어내 요약한 사례를 1건 확인했다. 근거 문서 기반 질의와 달리 자유 요약은 환각을 막을 장치가 약하다 — 실무 적용 시 입력 검증과 "근거 없으면 비워 두기" 규칙이 필요하다.
- 검색 색인이 단순해 문서가 수백 건으로 늘면 임베딩 기반으로 바꿔야 한다.
- 마스킹은 정규식 패턴 기반이라, 형식이 다른 번호나 이름 표기는 놓칠 수 있다. 실무 적용 전 탐지율 개선이 필요하다.
- 그럼에도 "민감한 정보를 다루는 현장에서는 로컬이 유일한 형태"라는 판단과, 구형 PC 사양에 맞춰 실제로 돌려 본 경험이 이 파일럿의 수확이다.
